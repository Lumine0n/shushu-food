# 狐友美食抓取脚本

从狐友（w.sohu.com）“上海大学”圈里找美食帖，先放进待审核清单，你确认后再并入正式美食清单。

```text
狐友 上海大学圈 ──fetch_sohu.py──> data/candidates.json（待审核）──review.py──> data/foods.json（正式清单）
                                   data/seen_posts.json（已抓过的帖子，下次跳过）
```

## 一、第一次准备（只做一次）

需要 Python 3.10 及以上。在仓库根目录打开终端：

```bash
pip install -r scraper/requirements.txt
python -m playwright install chromium
```

## 二、抓取

```bash
python scraper/fetch_sohu.py
```

默认会抓两个板块：“鼠鼠吃饭”和“校外商户排雷”，每个板块翻 5 页（每页 20 条），每次翻页之间随机等 3 到 4.5 秒。跑一次大约 1 分钟。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--boards 鼠鼠吃饭 全部` | 选板块，`全部` 是圈子首页的“新发” |
| `--max-pages 3` | 每个板块最多翻几页 |
| `--delay 5` | 翻页间隔秒数，别调得太小 |
| `--dry-run` | 只在屏幕上打印识别结果，不写文件 |
| `--headful` | 弹出浏览器窗口，看它在干什么 |
| `--comments` | 顺带抓美食帖下面的评论（需要登录，见下文） |

抓过的帖子 ID 会记进 `data/seen_posts.json`，下次运行自动跳过，所以可以放心反复跑。

## 三、审核

```bash
python scraper/review.py
```

按置信度从高到低，一条一条显示候选，你输入：

- `a`：通过，直接写进 `data/foods.json`
- `e`：先改再通过，逐个字段提示，直接回车表示保留原值，列表字段用逗号分隔，输入 `-` 表示清空
- `d`：丢弃
- `s`：跳过，下次再审
- `q`：保存并退出

菜名和店名都必须填，否则不能通过。`foods.json` 不存在时会自动创建。
如果店名加菜名已经在清单里（忽略空格和括号里的分店名），就不会新增一条，而是把那道菜的 `mentions` 加 1，`scene` 和 `tags` 取并集。

为保证写入后网页仍能正常筛选，审核时还会检查：

- 主料只能是：牛肉、鸡肉、猪肉、鱼虾、素食、其他
- 主食只能是：米饭、面、粉、汉堡披萨、其他
- 口味只能是：辣、不辣、清淡
- 价格必须是数字；场景只能是：一个人、聚餐、带走

抓取结果不一定能自动识别出这些字段。直接按 `a` 时如果字段不全，脚本会列出缺什么并跳过；请在它下次出现时按 `e` 补全后再通过。新版清单的编号是 `f001`、`f002`……，脚本会自动接着现有最大编号生成，不需要手填。

踩雷帖（`sentiment` 是 `negative`）不会出现在审核里，也不会进推荐清单，只留在 `candidates.json` 里当参考。

## 四、登录 Cookie（可选）

实测发现，**不登录也能看圈子的帖子列表**，所以默认不需要 Cookie。
只有评论内容要登录后才能看到；求推荐帖的答案大多在评论里，想抓评论就需要 Cookie：

1. 用浏览器登录 https://w.sohu.com
2. 按 F12 打开开发者工具，切到“网络 / Network”，刷新页面，点任意一个发往 `cs-ol.sns.sohu.com` 的请求，复制请求头里 `Cookie:` 后面的整串内容
3. 二选一：
   - Cursor 云端代理：在 Cursor Dashboard 的 Cloud Agents > Secrets 里新建 `SOHU_COOKIE`
   - 本机：在仓库根目录新建 `.env` 文件，写一行 `SOHU_COOKIE=刚才复制的内容`

`.env` 已经写进 `.gitignore`，不会被提交。Cookie 相当于你的登录状态，不要发给别人；账号密码不经过脚本。

## 五、识别规则（想调就改 extract.py 顶部的词典）

`extract.py` 不联网，只靠词典匹配：

- 已知店名：`data/foods.json` 里的店（没有的话用旧的 `data/foods.csv`），再加上一批常见连锁品牌
- 地点：食堂（益新、山明、尔美、水秀……）、商圈（新世纪、经纬汇、弘基广场……）、校区
- 菜名、主料、主食、口味、场景：各有一张词表，取值和问答网页的选项一一对应
- 价格：“13元”“20块”“11r”这样的写法
- 好评词（好吃、推荐、外瑞古德……）、踩雷词（避雷、难吃、拉肚子……）、提问词（有啥、求推荐……）

每条候选有一个 `confidence`（0 到 1）：命中已知店名、菜名、评价词、价格都会加分，求推荐的提问帖会减分。低于 0.3 的直接丢掉。

单独试一句话：

```bash
python scraper/extract.py "益新三楼肉夹馍～外瑞古德～"
```

## 六、隐私和频率

- 只保存帖子正文片段（最多 120 字，手机号、微信号、@某人会被替换掉）、发帖时间和帖子链接
- 不保存用户名、头像、用户 ID
- 只抓公开圈子；每次翻页间隔几秒，默认每次最多 10 页左右，别频繁跑

## 七、测试

不联网的离线测试，用 `tests/fixtures/` 里的样例 JSON：

```bash
python -m unittest discover -s scraper/tests -v
```

## 八、页面和接口（排错用）

- 圈子页：`https://w.sohu.com/circle/826522127825056896`
- 帖子链接：`https://w.sohu.com/circle/826522127825056896?feedDetail=<帖子ID>`
- 板块 ID：鼠鼠吃饭 `1288219670771609088`，校外商户排雷 `1144750393818032768`
- 列表接口：`cs-ol.sns.sohu.com/v8/circle/feed/list`，请求带签名 `sig`，所以不直接请求它，而是让真实页面去请求，脚本旁听返回的 JSON
- 字段：`sourceFeed.content` 是正文，`sourceFeed.score` 是发帖时间（毫秒时间戳），`pageInfo.hasMore` 表示还有没有下一页

如果哪天抓不到了，多半是狐友改版。先用 `--headful --dry-run` 看看页面上的板块标签还在不在，再对照上面的接口排查。
